# FigJam Board Layout — Recruitment Production Line

This is the spec for the FigJam board you'll use Wednesday. Build it in 15 minutes, walk into the meeting with it open. Encourage the team to add sticky notes live.

**Board name:** Recruitment as a Production Line — Brainstorm

**Frame order on the canvas (top to bottom):**
1. Framework — S&OP applied to recruitment
2. The Model (production line)
3. Handoff Contracts (the glue between stages)
4. Workstreams (four parallel tracks)
5. Infrastructure (the ready-to-present database)
6. Risks
7. Questions still open to brainstorm with the team

---

## FRAME 0 — Framework: S&OP applied to recruitment

Title: **"We're not inventing this. We're applying it."**

Subtitle: **"Sales & Operations Planning, the discipline that rewired manufacturing and fashion, now applied to recruitment."**

**Top row — S&OP cycle (5 sticky notes in a horizontal line, primary-color accent):**

```
[ 01 Demand ] → [ 02 Supply ] → [ 03 Match ] → [ 04 Execute ] → [ 05 Review ]
```

Below each, a smaller sticky with our mapping:
- 01 Demand → Member roadmaps + Decision Partner signals
- 02 Supply → Sourcing capacity + Candidate Ops throughput
- 03 Match → AI matching + stage capacity per workstream
- 04 Execute → Four parallel workstreams in motion
- 05 Review → Stage-level metrics (time-to-first-presentation, etc.)

**Bottom — Case Study Box (dark sticky, full width):**

> **Business case: Dell's Build-to-Order revolution (1990s)**
>
> Dell stopped keeping finished PCs in inventory. Instead, they held safety stock of components and assembled on order.
>
> - **Component safety stock** = our ready-to-present candidate database
> - **Build-to-order assembly** = match-on-demand recruitment
> - **Direct sales relationship** = the Decision Partner
>
> **Results:** Inventory 32 → 4 days. Delivery 6 weeks → 5 days. #1 PC maker by 2001.
>
> Dell's competitors weren't beaten on product. They were beaten on operating model. Same opportunity in recruitment — agencies are stuck running the slow flow. We can build the production line they don't even see.

## FRAME 1 — The Model (the hero visual)

Big, horizontal, takes up the top 40% of the canvas. This is what everyone looks at first.

**Layout:** Four large rectangles in a row, connected by thick arrows pointing right. Each rectangle is a stage. Color-code per stage so they're visually distinct.

```
[ STAGE 1 ]  →  [ STAGE 2 ]  →  [ STAGE 3 ]  →  [ STAGE 4 ]
  Sourcing      Candidate Ops    Recruitment      Decision Partners /
                                  / TAs            Account Growth
```

**Inside each stage: INPUT (top) → ACTIVITIES (middle) → OUTPUT (bottom). Use a distinct color for input/output stickies so the flow is obvious.**

---

**Stage 1 — Sourcing** (frame color: yellow)

- **Input sticky (light blue):** Sourcing Strategy
  - Role demand forecast
  - Location + seniority + market intel
  - Priority flags (urgent / standard / specialty)
- **Activities (yellow stickies):**
  - Active Pipelines (EAs, CSRs, SDRs, Bookkeepers, Accountants)
  - Assault Team (specialty / hard-to-fill)
  - Strategic Sourcing execution
- **Output sticky (dark yellow):** Raw candidate pool
  - Sourced profiles with basic data
  - Tagged by role family + priority

---

**Stage 2 — Candidate Operations** (frame color: orange)

- **Input sticky (dark yellow, same as Stage 1 output):** Raw candidate pool
- **Activities (orange stickies):**
  - Polished resumes + intro videos
  - Confirms availability + salary expectations
  - Standardized presentation cards
  - Keeps candidates warm
- **Output sticky (dark orange):** Ready-to-present database (the safety stock)
  - Polished resume + video
  - Confirmed availability + salary range
  - Last-contact date
  - Role tags for AI matching

---

**Stage 3 — Recruitment / TAs** (frame color: blue)

- **Input sticky (dark orange, same as Stage 2 output):** Ready-to-present database + incoming JD from member
- **Activities (blue stickies):**
  - AI matching: JD ↔ database
  - Builds presentation pages
  - Owns operational / HR relationship with candidate
  - Candidate interview preparation
  - Supports interviews with the member
  - HR-side connection with the member / customer
- **Output sticky (dark blue):** Shortlisted candidates + interview intelligence
  - up to 10 vetted candidates per JD
  - Presentation page link
  - Match rationale
  - Interview reports
  - Candidate insights for the Decision Partner's advisory conversation

---

**Stage 4 — Decision Partners / Account Growth** (frame color: green)

- **Input sticky (dark blue, same as Stage 3 output):** Shortlisted candidates + member context
- **Activities (green stickies):**
  - Strategic member relationship
  - Knows hiring roadmap + operations
  - Advises on the hire (sommelier role)
  - Manages expansion + retention
- **Output sticky (dark green):** Placement, retention, account growth
  - Hire confirmed
  - Member roadmap updated
  - Next hire identified (feeds back into Stage 1)

---

**Closing the loop:** Curved arrow from Stage 4's output back to Stage 1's input. Label: **"Demand signal feedback loop"**.

**White Glove note (amber/highlight sticky spanning Stage 3 and Stage 4):**

> **Note · White Glove Exception**
> For White Glove customers, Stage 3 and Stage 4 are led by the same White Glove Advisor. The Advisor owns both recruitment execution and the strategic decision-partner relationship. The production line still applies, but the handoff between 3 and 4 happens inside one head.

## FRAME 2 — Handoff Contracts (small frame, below the production line)

Title: **"The glue between stages — no verbal pass-offs"**

Simple 4-row sticky note column:

- **Sourcing → Candidate Ops:** Sourced profile + basic data + priority tag
- **Candidate Ops → Recruitment:** Polished profile + confirmed availability + salary range
- **Recruitment → Decision Partners:** up to 10 matched candidates + presentation page + match rationale + interview reports + candidate insights
- **Decision Partners → Sourcing (loop):** Demand signal — next roles needed, by which member, by when

---

## FRAME 3 — Workstreams (four parallel tracks)

Title: **"Four parallel workstreams. One execution gate."**

Subtitle: **"We build in parallel, not in sequence. The system is ready to execute the day Candidate Ops starts delivering."**

Four columns, one per workstream. Each column has a status pill at the top, then Where We Are / What's Left. (Open questions for each workstream live in Frame 6.)

**Workstream 1 — Sourcing** (status: green "Mostly in place")
- Where we are: Outbound running. Active pipelines for most-frequent roles. Unified Recruitment + Sourcing effort already producing.
- What's left:
  - Give it formal structure (Active / Assault / Strategic split)
  - Name leads per sub-function
  - Document the handoff contract with Candidate Ops

**Workstream 2 — Candidate Operations** (status: amber "To build")
- Where we are: Brand new department. Profile: efficient, async-first, follows instructions, attention to detail.
- What's left:
  - Stand up the team
  - Build AI tools: weekly availability confirmation, salary refresh, resume / video polish, warm-keep cadence

**Workstream 3 — Recruitment / TAs** (status: green "Already performing")
- Where we are: TA team already delivering across Passport and Core.
- What's left:
  - Add Pod Lead figure(s) to keep every HR on track
  - Build AI tools: matching tool, presentation page builder, interview report creator

**Workstream 4 — Decision Partners** (status: teal "To define")
- Where we are: Very specific profile. Initial thinking: Account Manager + Pod Lead blend. First names: Manuel, Manuela, Feli, Miguel (or similar profiles).
- What's left:
  - Scope the role precisely (primary focus)
  - Identify the right people
  - Define the comp model
  - Set the member-handling protocol

**Build Principle Banner (place below the four columns, full width, amber-accent sticky):**

> **Build in parallel** — All four workstreams advance at the same time.
> **Execution gate** — We run the new model once Candidate Ops is delivering. That's the only hard dependency.
> **Primary focus** — Scoping the Decision Partner / Account Growth role. It's the linchpin.

## FRAME 4 — Infrastructure: The Ready-to-Present Database

Title: **"The Safety Stock — Infrastructure"**

Subtitle: **"This database is what makes the whole line fast. If it isn't well built, nothing downstream is."**

Layout: 4 columns of sticky notes, plus a recommendation banner below.

**Column A — Where it lives**
- Single source of truth, API-accessible
- Queryable by AI matching tool, presentation builder, dashboards
- No duplicates across spreadsheets, Notion, recruiter heads
- **Strong candidate:** Airtable (already in use, MCP integration ready)

**Column B — Field structure (machine-readable)**
- Identity: name, location, country, time zone
- Role tags: primary + adjacent roles (multi-select)
- Seniority + experience years
- Salary range (confirmed, USD)
- Availability: status + last-confirmed date
- Assets: polished resume URL + intro video URL
- Tech / tools stack (multi-select)
- Language proficiency
- Source channel + sourced-by
- Lifecycle status: Sourced / Polishing / Ready / Placed / Paused / Inactive

**Column C — Access model**
- Sourcing: creates initial record (Sourced status)
- Candidate Ops: writes everything, owns promotion to Ready, owns the database
- Recruitment / TAs: read-only, matches and builds presentation pages
- Decision Partners: read-only, uses match output + interview intel

**Column D — Lifecycle**
- Entry: only Candidate Ops promotes to Ready (all fields + assets required)
- Refresh: weekly availability + salary check
- Decay: 30 days no refresh → flagged. 60 → Paused. 90 → Inactive.
- Reactivation: through Candidate Ops only
- On placement: Placed status, stays in DB for replacement scenarios

**Recommendation Banner (below the 4 columns, amber accent):**

> **Build v1 in Airtable.** Same base across all four workstreams. Same MCP integration we already run. Layer a custom front-end later if Airtable's UI becomes the bottleneck. The data model stays portable.

## FRAME 5 — Risks

Title: **"Where this could go sideways"**

Three columns:

| Risk 1: Handoff Tax | Risk 2: Losing Surfacing Speed | Risk 3: Can't Depend on One Person |
|---|---|---|
| Sloppy handoffs eat the efficiency gains | Smaller ready-to-present DB could slow us down | If only one person can run it, it isn't built right |
| **Mitigation:** Documented input/output specs. SLAs. Single source of truth. | **Mitigation:** Continuous feed into safety stock. Assault Team for urgent. Watch time-to-first-presentation. | **Mitigation:** Stage leads own throughput. We manage the system, not the requests. |

Leave empty sticky notes below each column labeled **"Add your concerns here"** for the live brainstorm.

---

## FRAME 6 — Questions still open to brainstorm with the team

Title: **"Questions still open to brainstorm with the team"**

Subtitle: **"Grouped by area. None of these need to be solved today. All of them need to be talked through."**

Six grouped sticky note columns (or six cards):

**Org & ownership**
- Who leads each stage?
- What's the single shared system of record across all four workstreams?

**Candidate Operations**
- How much of the work do we automate from day one vs. start manual and automate later?

**Recruitment / TAs**
- How many Pod Leads / Team Leads do we need? Two? Three?
- How do we distribute the workload across them?

**Decision Partners**
- Comp model: sales-style commissions, hybrid, or something else?
- Are Manuel, Manuela, Feli, Miguel the right starting bench, or are we missing profiles?

**The Database**
- Can the recruiter's interview report auto-enrich the candidate's profile in the ready-to-present database? If yes, the DB compounds in value with every interaction. Big upside, big design question.

## How to use the board in the meeting

1. **Open with Frame 0 — Framework.** One minute. Set the frame: "this is S&OP applied to recruitment, here's the Dell parallel." Anchors the credibility.
2. **Frame 1 — The Model.** Walk left to right. Two minutes per stage. Don't go deep yet.
3. **Frame 2 — Handoff Contracts.** Read each contract aloud. This is where most of the work goes if we get serious.
4. **Frame 3 — Workstreams.** Show parallel build + execution gate. Anchor the "primary focus = Decision Partners".
5. **Frame 4 — Infrastructure.** Walk the database design. Get an explicit yes/no on Airtable as v1.
6. **Frame 5 — Risks.** Read each risk out loud. Invite the team to add sticky notes with their own concerns.
7. **Frame 6 — Questions.** Spend the most time here. Pick the 3 or 4 that block the most progress. Capture answers live.

---

## Build tips

- Use FigJam's pre-built shapes. Don't waste time on visuals.
- High-contrast stickies (yellow, orange, blue, green) read better than Sagan brand colors on a working board.
- Add a small "Last updated: May 8" note in the corner.
- Share the board link in the Google Doc pre-read so the team can poke at it before Wednesday.

**Time to build:** 20 minutes if you don't overthink it. The board is meant to get marked up, not admired.
